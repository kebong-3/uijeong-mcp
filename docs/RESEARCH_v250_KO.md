## 설계 판단

1. **근거 없는 자동 답변을 늘리지 않기.** 과거 회의록은 당시 발언의 근거입니다. 현재 실적은 현재 문서로, 이행 완료는 증빙으로 확인해야 합니다. 서버는 원문 연결과 검토 항목을 제공하고, 연결된 AI가 출처 범위에서 문장을 작성하도록 했습니다.
2. **수치의 모양보다 비교 기준을 먼저 보기.** “1억원 대 120000천원”은 환산이 필요합니다. “본예산 대 최종예산”, “실인원 대 연인원”은 의미 있는 증감률인지 먼저 확인해야 합니다. %와 %p도 구분했습니다.
3. **도구를 직접 여러 번 조합하는 부담 줄이기.** 준비자료 도구가 수집과 근거 식별자·확인사항을 함께 제공합니다. 추가 검색이 필요한 경우 실행 가능한 다음 도구 인자를 반환합니다.
4. **검수의 한계까지 데이터로 남기기.** 문구가 일치하더라도 의미상 입증을 자동 판정하지 않습니다. `semantic_support=NOT_ASSESSED`와 담당자 검토 상태를 유지합니다.
5. **장애를 정책 금지로 오인하지 않기.** robots.txt의 일시적인 조회 실패를 6시간짜리 접근금지로 저장하던 경로를 수정했습니다. 실제 금지 규칙은 계속 준수하고, 조회 실패는 다음 요청에서 재확인합니다.

위 1~5는 공식 자료와 첨부 코드 분석을 바탕으로 한 개발 판단입니다. 검색 정확도 향상률이나 업무시간 절감률을 측정한 결과는 아닙니다.

## 조사 범위의 한계

공식 감사결과 게시물의 제목·첨부 존재까지 확인했으며 PDF 내용을 이번 서버에 자동 수집·분석한 것은 아닙니다. 서구의회 안내 페이지의 법정기한을 코드에 고정하지 않았습니다. 현행 법령 해석·기관 내부 제출기한은 별도 확인 대상입니다. 원문 표본 검증 범위와 실제 운영 수집 경로의 제한은 검증보고서에 따로 기록합니다.
