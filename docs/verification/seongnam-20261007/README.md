# 성남시 스마트도시 재검수 개선 — 4.1.6-public.1

## 기준 및 범위

요구사항: 사용자가 제공한 2026-10-07 성남시 스마트도시 개선방안 인수인계서.
기준 main: `4008ac974186a60f557a8d8fc38727d44d55dd29`.
기준 실행: `541cd09b95fa233d5bed003045a5b49a28dd5c31`, `4.1.5-public.2`.
기존 공개·무인증·읽기전용 40개 도구, Render 단일 인스턴스, API 키, 의존성 버전을 유지한다.
ChatGPT Sites 별도 서비스, 다른 저장소 및 요금제는 변경하지 않는다.

## 변경 사항

1. 자연어에서 정책 주제·기간·예산 단계·의회 의도·메타 명령을 분리한다. 명시한 인용 고유명은 보존한다.
2. 스마트도시/스마트시티를 별개 검색어로 조회하고 같은 회계연도·기준일·지자체·회계·사업코드로 중복을 제거한다. 동의어는 검색 힌트이며 동일사업 확정이 아니다.
3. CLIK 발언자 직함의 영문·숫자를 인식하고 질문/답변을 분리한다. 변환된 평문 범위·발언 표지·원문 계보를 보존하며 HTML 바이트/PDF 쪽수로 소개하지 않는다.
4. 부서명이 명시된 질문에 대한 국장 답변을 대리답변 후보로 분류하고 ANSWERER_TITLE/AGENDA_SECTION/PARENT_BUREAU_CONTEXT/TEXT_MENTION_ONLY를 노출한다. 조직도 관계는 검증했다고 표시하지 않는다.
5. 자치법규 검색은 검증된 지역명 접두어를 상류 제목검색에 먼저 적용한다. 정확한 제목 일치를 먼저 정렬한다. CLIK/재정 코드를 법령기관코드로 전용하지 않는다.
6. 표준 search/fetch는 공통 자연어 분해기와 근거 묶음 조회를 재사용한다. 이름은 실제 조회된 발언의 정렬 힌트일 뿐 추정 발언자를 생성하지 않는다.
7. 완전한 회의 메타데이터가 같은 목록은 대표 문서로 묶고 alternate_docids를 보존한다. 목록 중복은 본문 동등성 입증이 아니다. 대표 원문 실패 시 제공된 다른 판본을 제한적으로 확인한다.
8. 대형 응답은 근거 3~5건과 얇은 문서목록, snapshot, 정확한 이어보기 위치를 먼저 보존한다. 전체 근거는 손실 없는 압축 스냅샷에 저장하며 압축·해제 상한과 해시를 검사한다.
9. 공개 max_docs 등 입력 상한을 실제 Tool Schema에 반영한다. 조례 원문의 기존 max_chars=5000 제한도 유지한다.
10. 실행/배포 상태와 표본 조회 범위 상태를 분리한다. NO_CHECK_SINCE_RESTART와 CHECK_FAILED를 구분한다.
11. 공식 성남시의회 문서키만 좁은 허용목록으로 보존한다. 인증키와 추가 자격증명은 계속 마스킹하며 영구주소를 임의 생성하지 않는다.
12. 통합 근거 묶음에 최종 메타데이터 검토와 후보 연결 엔터티를 자동 부착한다. 원문 사실·적법성·동일사업을 인증하지 않는다.

## 금액 단위 — 미완료인 공식 확인을 명시

공식 공공데이터포털 설명은 읽었지만 QWGJK 금액 필드 각각의 단위는 확인되지 않았다.
따라서 amount_unit을 임의로 원으로 고치지 않는다. unit_verified=false,
RAW_VALUE_ONLY, BLOCK_NUMERIC_NORMALIZATION 및 필수 답변 주의문구를 제공한다.

공식 확인 출처:
- https://www.data.go.kr/data/15138857/openapi.do
- https://www.lofin365.go.kr/portal/LF5120000.do?pdtaId=0GAR4HBB8LWEBSL4NIHZ817053
- https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=ordinListGuide

다른 지자체 공개화면에 표시된 '원'은 QWGJK 전체 필드의 단위 증명으로 사용하지 않았다.
최종 숫자 환산 차단 시험의 PASS는 공식 단위 확인 완료를 뜻하지 않는다.

## 재현 결과의 차이

첨부 문서의 모든 관측을 현재 사실로 복사하지 않는다. 이번 수정 전 실제 캡처에서는
정확한 성남시 조례가 이미 1순위였고 부서 답변도 반환됐다. 다만 일반 조례검색의
전국 목록 스캔, 복잡한 명령어 오염, 표준 검색 0건, AI혁신국장 발언 병합,
큰 부서 근거 묶음의 snapshot 저장 실패는 직접 확인됐다.

## 검증 방법

- 기존 회귀시험과 새 Golden 시험: `python -m pytest -q` (격리된 상태 DB).
- 실제 12개 요구 시나리오 및 추가 검사: `python scripts/verify_seongnam.py --output-dir <dir>`.
- 기존 공개 40종 최소 호출: `scripts/verify_recovery.py`와 기존 inventory를 재사용.
- 모든 실호출은 2026-10-07 요청 범위 및 실제 반환 기준일을 분리한다. 검증 일시는 실제 실행 시각으로 기록한다.
- 제출용 법률 판단, 전국 전수 정확도, 40명 동시 부하, 타 계정 앱 명세 갱신은 검증 범위가 아니다.
- 서버가 필수 주의문구를 반환해도 모든 하위 LLM의 응답 준수까지 서버가 강제할 수는 없다.
