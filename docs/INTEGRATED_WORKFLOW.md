# 지방의회·예산·조례 통합 흐름

직원은 같은 MCP 주소를 사용하고 질문에 필요한 분야만 조회한다. 별도의 유료 모델을 서버에서 실행하지 않는다. ChatGPT 계정별 도구 지원이나 사용량 제한을 변경하지 않는다.

- 단순 질문: 해당 도구로 직접 조회한다.
- 복합 질문: `local_workflow_plan`에서 지역·회계연도·조례 기준일을 확인하고 필요한 조회 순서를 얻는다. 이 도구는 외부 조회를 하지 않는다.
- 의회: `council_evidence_bundle` 소량 검색 후 필요한 원문만 `council_read_source`로 확인한다.
- 예산: `budget_api_catalog`의 실제 매개변수를 확인하여 `budget_fetch_api`를 사용한다. 계산은 `budget_calculate`를 사용하며, 인자 형식을 모를 때만 `budget_calculation_schema`를 먼저 확인한다.
- 조례: `ordinance_search`의 공식 ID를 선택하여 `ordinance_get_document`로 시행일과 조문을 확인한다.
- 답변 전: 필요한 경우 `local_evidence_review`로 출처, 지역, 연도, 단위, 시행일 누락을 점검한다. 이는 입력된 메타데이터 점검이며 사실·법률 검증이 아니다.

서로 다른 지자체 사례, 회계연도, 본예산·추경·결산 수치, 현행·연혁 조례를 섞지 않는다. 의원의 요구를 확정 정책으로 소개하지 않는다. 조례가 있다고 예산 편성·집행이 자동으로 허용된다고 판단하지 않는다. 오류와 0건, 일부 열람을 구분한다. 검색 결과가 없으면 전체 자료 부재로 확대하지 않는다.

복합 질문 예: “광주 서구 2026년 경로당 추경 심사 관련 발언과 예산, 지원 조례 근거를 함께 검토해줘.” 세 분야를 필요한 범위에서 조회하고, 확인된 결론 → 원문 근거와 기준일 → 계산 조건 → 미확인 사항 순으로 답한다.
