# 4.0 통합 검토 기록

작성일: 2026-09-30 (한국 시각)

## 담당과 회의 결과

실제 개발 작업은 예산·조례·업무흐름·안정성 네 에이전트가 분담하고 총괄이 통합했다. 제품 실행 시 AI 네 개가 자동 협의하는 구조를 의미하지 않는다.

| 담당 | 결과 | 교차검토 반영 |
|---|---|---|
| 예산 | 기존 예산 코어를 동일 프로세스에 포함, 9가지 계산을 단일 도구로 제공 | 공개 사용자 자료 저장 제거, 계산 입력 명세는 필요 시만 조회 |
| 조례 | 공식 검색·원문·비교·제개정 검토 | 사용자 초안과 공식 조회 구분, 다른 문서 버전 비교 거부, 원문 해시 확인 |
| 업무흐름 | 질문별 필요한 분야와 근거 누락 점검 | 모호한 지역은 확인 요청, 계획을 조회 결과로 표현하지 않음 |
| 안정성 | 익명 HTTP·도구 목록·독립 호출·오류·시간초과 검증 | 공통 응답 경계, 긴 본문 중복 방지, 비밀값 제거, 실패 상태 유지 |

합의: 기존 직원 주소 유지, 단일 무인증 Streamable HTTP 서버, 다른 무료 서버를 중계하지 않음, 별도 유료 LLM 호출 없음. 현재 규모의 실사용 안정성에 집중하며 별도 DB·워커·추가 유료 인스턴스를 만들지 않는다.

## 확인한 시험

- 통합 저장소 회귀시험: 592개 통과.
- 익명 실제 ASGI HTTP 초기화·40개 도구 목록·의회/예산/조례/업무계획 호출 통과.
- 서로 다른 두 클라이언트의 예산 계산 결과 독립성 확인.
- API 실패·시간초과를 오류로 유지, 키 제거, 큰 응답 중복 억제 확인.
- 기존 STDIO 및 인증 HTTP 프로토콜 회귀시험 통과.
- 예산 원본 핵심 계산/API 시험 129개, 조례 원본 핵심 시험 121개 통과(각 소스 저장소에서 별도 수행; 통합 592개와 합산하지 않음).

이는 로컬·모의 상류 시험이다. 운영 배포·실제 API 시험은 `scripts/verify_unified.py`와 별도 실조회로 확인한다. 직원의 실제 ChatGPT 무료 계정에서 앱 선택부터 답변까지의 전 과정은 계정별 후속 확인 대상이다.

## 운영 전 실조회에서 발견한 수정

기존 조례 서버의 지방자치법 원문 호출에서 장·절 표제를 조문 중복으로 처리하는 오류를 확인했다. 공식 응답의 `조문여부=전문`을 조문에서 제외하고 실제 중복 조문 거부는 유지했다. 긴 법령은 조문·부칙·별표와 문자 구간을 나누어 무손실 이어읽기하도록 보완했다.

## 배포와 복구

기존 main 기준: `10ffde8bed3cea34642c2d842828b62b4ceedd7e`.
유료 인스턴스와 기존 MCP 주소를 유지한다. 원본 예산·조례 저장소 및 서비스는 수정하거나 삭제하지 않는다. 필요 시 이전 의회 버전 커밋으로 되돌릴 수 있으나, 이전 render.yaml의 무료 plan을 그대로 재적용하지 않도록 주의한다.

API 키는 Render 내부 참조로 복사하고 설정 확인 후 `sync: false`로 전환해 유지한다. 소스나 문서에 비밀값을 기록하지 않는다. 코드 변경 뒤 `python scripts/build_manifest.py`를 실행하고 런타임 해시를 배포 서버와 대조한다.
