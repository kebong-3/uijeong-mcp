# 지방의회 MCP 2.5.0-rc.1 개선·검증보고서

작성: 2026-09-21 한국시간 / 원본: 사용자 제공 2.4.0-rc.1 / 목적: 공무원의 지방의회 질의응답·답변자료 준비 지원

## 1. 결과

**새 버전의 전체 소스와 교체 패키지를 작성했습니다. 기존 386건과 신규 60건, 총 446건의 pytest가 통과했고 실패·제외는 0건입니다. 실제 MCP SDK 1.30.0의 stdio·HTTP 통신 시험도 통과했습니다.**

이번 산출물은 `2.5.0-rc.1`입니다. 운영 서버 배포·실제 OAuth 로그인·CLIK 인증 조회가 완료되지 않아 최종 운영 검증판으로 표시하지 않습니다.

## 2. 실무 기능의 변화

| 항목 | 제공된 2.4.0 | 이번 2.5.0 |
|---|---|---|
| 답변 준비 흐름 | 검색·근거·답변카드 등을 개별 호출 | 검색→인용ID→과거 문답·현재자료·준비질문·확인사항을 한 호출로 구성 |
| 초안 검수 | 숫자 표기·표현·제공자료 발췌 연결 중심 | 실제 스냅샷 발언과 문장별 연결, 변형 직접인용·중복문장 위치·미연결 질적 주장까지 점검 |
| 예산·성과 비교 | 같은 행 동일 단위라는 전제로 산술 계산 | 사업·기관·모집단·기간·회계기준 대조. 기준 불일치 시 계산 보류, 금액 환산·%p 구분 |
| 과거 답변 대조 | 개별 검색 결과를 사용자가 조합 | 두 발언을 정확한 원문·발언 위치·수치·조건 단서와 함께 비교 |
| 실무 안내 | 여러 도구 설명·예시 | 한국어 답변준비 프롬프트와 MCP 안내 리소스, 실제 공식 문서 확인 경로 추가 |
| 기존 초안 점검 오류 | 초안 위치만 있으면 숫자가 claim_linked로 표시될 수 있음 | 유효한 제공자료 발췌 연결까지 확인한 경우에만 표시 |
| robots 조회 장애 | 통신 실패를 접근금지처럼 6시간 보관할 수 있음 | 해당 요청의 수집은 보류하고 다음 요청에서 재확인. 실제 금지 규칙은 계속 준수 |
| 긴 원문 읽기 | 일부 CLIK 읽기 경로에서 동기 파싱 | 해당 경로도 별도 스레드에서 파싱 |

추가 도구는 `council_prepare_response`, `council_audit_claims`, `council_compare_metrics`, `council_compare_evidence`입니다. 기존 도구 입력 계약과 인증 설정, SQLite 테이블 구조는 유지했습니다. work 프로필은 14→18개입니다.

## 3. 대표 오류 사례에서의 처리

- **없는 인용문:** 유효한 citation_id가 있더라도 발췌문이 실제 저장 원문에 없으면 표시합니다.
- **과거 발언으로 현재 사실 확정:** 현재 주장에 과거 회의록만 연결하면 별도 검토 대상으로 표시합니다.
- **조건 삭제:** “예산이 확보되는 경우” 등 조건·부정 단서가 달라지면 원문 대조를 요구합니다. 규칙 기반 단서이므로 모든 의미 왜곡을 탐지하는 것은 아닙니다.
- **근거 없는 질적 주장:** 숫자가 없어도 “모든 문제가 해결됐다”처럼 연결하지 않은 내용은 미연결 구간에 남습니다. 의미를 자동 판정하는 방식이 아니라 초안 전체의 인용 연결 범위를 대조하는 방식입니다.
- **같은 문장 반복:** 초안에 동일 문장이 여러 번 있으면 start_char를 요구합니다.
- **본예산/최종예산 혼합:** 두 기준이 다르면 증감률을 계산하지 않습니다.
- **1억원/120000천원 비교:** 같은 비교기준이면 원 단위로 환산해 20000000원·20.00% 증가를 반환합니다. 이는 합성 입력의 계산 예입니다.
- **80%/90% 비교:** 차이를 10%p로 표시합니다. 0 기준 증감률은 null입니다.
- **자료 부족·장애:** EMPTY/PARTIAL/ERROR를 구분하고 다음 검색 인자·미열람 회의·원문 회수 경로를 제공합니다.
- **출력 한도 초과:** 축약 사실과 회수 경로를 남기고, 검수 결과가 축약되면 전체 초안 검수가 완료됐다는 표시를 해제합니다.

문구 일치와 실제 사실·의미 입증은 다릅니다. `semantic_support=NOT_ASSESSED`, `ready_for_submission=false`를 유지하며 최종 제출은 담당자가 확인합니다.

## 4. 실제 실행 검증

| 검증 | 결과 | 범위 |
|---|---|---|
| 원본 2.4.0 전체 pytest | 386건 통과 | 이번 환경에서 실제 재실행 |
| 개선판 전체 pytest | **446건 통과, 실패 0·제외 0** | 기존 386 + 신규 60 |
| 실제 SDK stdio | 통과 | initialize·tools/list·실제 도구 호출·구조화 결과·오류 계약 |
| 실제 SDK Streamable HTTP | 통과 | 로컬 TCP 서버·정적 Bearer·401/403/413·신규 도구 호출 |
| 프롬프트·리소스 | 통과 | 실제 SDK로 목록·안내 리소스 읽기 |
| 런타임 코드 대조 | 통과 | 실제 SDK 상태 응답에서 manifest MATCH 확인 |
| work 입력 명세 | 출력 완료 | 실제 SDK의 18개 도구 명세를 JSON으로 보관 |
| 기존 추가 회귀 스크립트 2종 | 모두 통과 | pytest 446건에 별도 가산하지 않음 |
| 제공자료 저장 방지·이용자 분리 | 합성 업무시험 통과 | 비공개 표식이 공개 근거 스냅샷에 없는지, 다른 사용자 스냅샷 거부 확인 |
| 공식 HTML 원문 표본 | 2건 확보·파서 검사 | 아래 별도 설명 |
| 운영 서버·ChatGPT OAuth 로그인 | 미실시 | 별도 인증서버와 운영 계정 필요 |
| CLIK 인증 실조회 | 미실시 | 실제 API 키를 제공받지 않음 |
| 운영 서버 배포 | 수행하지 않음 | GitHub·Render는 변경하지 않음 |

Python 3.12에서 실행했습니다. Python 3.11은 CI에 구성했지만 이번 환경에서 직접 실행한 결과로 주장하지 않습니다. HTTP/OAuth 경계 관련 단위시험의 합성 응답은 실제 OAuth 로그인 성공을 의미하지 않습니다.

## 5. 공식 원문 표본 확인

서구의회 최근회의록 목록에서 10개 행을 파싱했고, **2026-07-28 기획총무위원회·사회도시위원회 원문 HTML 2건**을 별도로 내려받아 확인했습니다.

- 파싱한 발언 수: 각각 282개, 386개.
- 각 발언자 표기와 발언 본문이 독립적인 HTML 텍스트 추출 결과 안에 존재하는지 대조했습니다. 화면 배치용 공백·줄바꿈을 제외한 비교에서는 모두 일치했습니다.
- 각 회의에서 예산 관련 질의답변 표본 2쌍의 질문·답변 위치와 본문 존재도 확인했습니다.
- 최초의 공백까지 포함한 단순 문자열 비교는 줄바꿈 차이로 불일치했습니다. 이 기록을 숨기지 않고, 공백 정규화 비교 방식과 결과를 함께 남겼습니다.

이는 **원문 표본에 대한 파서 구성요소 검증**입니다. 전체 회의록의 의미상 질의답변 연결 정확도·누락률·성능을 측정한 결과가 아닙니다.

검증 환경의 일반 네트워크 경로로 공개 원문은 확보했지만, 서버의 DNS 사전 검사·직접 통신 경로에서는 수집이 보류됐습니다. 보안 검사를 제거하거나 운영 수집 경로를 우회하도록 소스를 바꾸지 않았습니다. 따라서 공식 HTML 확보와 운영 MCP의 처음부터 끝까지 실제 수집 성공을 같은 것으로 표시하지 않습니다.

근거: `docs/verification/v250/live-capture-parser.json`, `live-site-list.json`. 실제 원문 주소와 HTML SHA-256을 기록했으며 전체 원문 HTML은 배포 패키지에 넣지 않았습니다.

## 6. 공식 자료 조사 반영

[서구의회 행정사무감사·조사결과](https://www.gjsc.or.kr/kr/dataroom/bbsInvestigation.do)가 회의록과 별도로 공개되는 점을 반영해, 감사 결과·현재 현황·후속조치 증빙을 따로 확인하도록 했습니다. [CLIK Open API](https://clik.nanet.go.kr/potal/guide/openApi.do)의 호출 한도를 고려해 기존 수집 상한과 스냅샷 재사용을 유지했습니다. [MCP 도구 규격](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)을 기준으로 구조화 결과·오류 전달 계약을 실제 SDK에서 검증했습니다.

조사자료와 개발 판단의 상세 대응표는 `docs/RESEARCH_v250_KO.md`에 있습니다.

## 7. 남아 있는 한계와 운영 전 확인

이 버전은 다음을 자동 완성하지 않습니다.

- 전국 지방의회 홈페이지 전수수집, 모든 최신 회의록의 즉시 반영.
- PDF/HWP 첨부의 자동 수집·OCR·현행 법령 해석.
- 임의 문장의 의미상 참·거짓 검증이나 법적 적합성 판단.
- 담당자 자료의 진위 확인, 실제 이행 완료 판정.
- 외부 OAuth 인증서버 구축, 실제 클라이언트 로그인·운영 부하 검수.

제공자료의 180일 경과 표시는 기본 재확인 기준일 뿐 유효기간·허위 판정이 아닙니다. 수치의 비교기준은 사용자가 정확히 입력해야 합니다. 정적 Bearer를 공유하는 이용자는 같은 인증 범위를 사용하므로 개인별 분리가 필요하면 기존 OAuth 사용자 구분 기능을 운영 검수해야 합니다.

운영 전에는 실제 접속 인증과 `council_status(live=True)`, 원문 3건 이상의 회의일·발언자·연결 대조, 사용자별 접근 확인을 완료하세요.

## 8. 재현 파일

- `pytest.log`, `pytest.xml`: 최종 446건 결과.
- `baseline-386.log`: 수정 전 원본의 이번 재실행 결과.
- `protocol.json`, `protocol.stderr`: 실제 SDK stdio·HTTP 결과.
- `runtime-work-schemas.json`: 실제 work 프로필 도구 명세.
- `environment.json`, `verification-summary.json`: 환경과 범위 요약.
- `development-attempts/`: 수정 도중의 실패 기록. 최종 결과와 구분.
- `docs/examples-v250/`: 실행 가능한 합성자료 예시. 실제 서구 사업 자료가 아님.

기존 시험의 버전·프로필 개수 기대값만 새 버전에 맞게 갱신했습니다. 기존 사업 규칙 검증을 삭제하거나 시험을 건너뛰지 않았습니다. 초기 기능 검증에서 발견한 선택적 단위 필드의 재정규화 오류도 수정한 후 전체 시험을 통과했습니다.
