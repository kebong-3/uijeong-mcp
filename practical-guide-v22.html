의정소통 MCP 2.2 — 지방공무원 의회 대응 실무 도구

2026년 9월 19일 · 제공된 클로드 개선본 v2.1.0을 분석하고 확장한 소스·로컬 검증본

개발 방향

목표는 담당자가 회의 전에 근거와 수치를 준비하고, 회의 중에는 확인된 사실로 설명하며, 회의 후에는 요구사항과 조치 증빙을 빠뜨리지 않도록 돕는 것입니다. 의원별 성향·공격성·심기를 점수화하거나 회피 답변을 만드는 기능은 두지 않았습니다. 설명의 정확성과 존중하는 표현으로 협력적인 의회 대응을 지원합니다.

검색만으로 답변자료가 완성되지는 않습니다. 과거 회의록, 현재 부서 자료, 담당자의 검토가 연결되어야 합니다. 이번 버전의 핵심은 이 세 가지를 분리해서 보여 주는 실무 흐름입니다.

무엇이 달라졌나

실무 단계 구현한 기능 담당자에게 주는 결과
회기 전 회의 유형별 준비표 준비 일정, 주제별 확인 질문, 필요한 자료
쟁점 정리 실제 발언에 연결한 답변카드 질문·현황·핵심 답변·근거·후속조치의 작성 틀
답변 검토 초안과 제공자료 대조 숫자·단위 근거 누락, 포괄적 확약, 모호한 표현 등 확인 후보
예산·결산 수치 산술 점검 증감액·증감률·집행잔액·집행률과 비교 기준 누락
회의 후 후속조치 증빙 확인표 보고 상태, 담당부서, 명시된 기한, 증빙 구비 여부
근거 재확인 기존 검색 묶음 이어보기 같은 자료의 실제 발언·후속조치 식별자, 원문 회수 경로

지원하는 준비 유형은 행정사무감사, 예산심사, 결산심사, 조례심사, 구정질문, 5분자유발언, 업무보고의 7가지입니다. 일정은 회의일을 기준으로 한 내부 준비 제안이며 법정 기한이 아닙니다. 질문은 준비용 점검 질문이며 특정 의원의 실제 질문을 예측한 결과가 아닙니다.

답변카드는 검토 틀과 근거를 반환합니다. MCP 자체가 생성형 모델을 호출해 완성 답변을 쓰지는 않습니다. 연결된 AI가 근거와 현재 자료로 초안을 작성하고, 담당자가 확인하는 구조입니다. 초안의 숫자·표현 검사는 규칙 기반이며 의미의 진실성이나 법적 적합성을 승인하지 않습니다.

클로드 개선본 분석과 반영

클로드 개선본의 응답 크기 제한, 중복 본문 제거, 근거 수 상한, 스냅샷 보관 한도, 도구 프로필 분리는 유지했습니다. 원본 v2.1.0의 테스트 211건을 먼저 실행해 통과를 확인했습니다.

다른 의회를 사용할 때는 “서울 광진구”, “부산 서구”처럼 시·도와 시·군·구를 함께 지정하세요. 준비표의 기본 의회는 광주 서구입니다. 입력에서 다른 의회를 지정하면 후속 검색 인자에도 그대로 전달합니다. ‘서구’만으로 지역을 임의 확정하지 않습니다.

현재 자료 입력 예시

AI에게 문서 전체를 무조건 제공하기보다 업무에 필요한 내용과 근거 위치를 함께 전달합니다. 다음은 형식 설명용 가상 자료입니다.

{
  "facts": [{
    "id": "F1",
    "text": "2026년 본예산 편성액은 1240백만원이다.",
    "document_ref": "가상 예산설명자료 12쪽",
    "as_of": "2026-09-19",
    "unit": "백만원",
    "fiscal_year": 2026
  }]
}

담당자 제공자료는 항상 USER_PROVIDED, 서버 미검증으로 표시합니다. 초안 문장과 자료의 단어·숫자가 일치해도 사실의 정확성이 자동 확인된 것은 아닙니다. 예산의 편성액·집행액, 본예산·최종예산, 회의연도·회계연도는 구분해 검토해야 합니다. 입력 숫자는 쉼표 없는 정수 또는 소수 문자열을 사용하며, 행 안에서는 같은 단위를 사용합니다.

신규 실무 도구는 제공된 초안·부서 자료·후속조치 갱신 내용을 서버 데이터베이스에 저장하지 않습니다. 따라서 다음 작업에서 다시 제공해야 하며 공동 업무관리 시스템처럼 변경 이력이 유지되지는 않습니다. 공개 검색자료의 기존 스냅샷 보관은 유지합니다. 사용하는 AI 클라이언트의 대화 저장 정책은 별개입니다.

도구 구성

도구 사용 목적
council_plan_session 회의 유형별 준비표
council_get_evidence snapshot_id로 실제 근거·후속조치 후보 이어보기
council_build_issue_card 선택한 event_id와 현재 자료를 연결한 쟁점 카드
council_review_answer 초안의 수치·표현·제공근거 연결 검사
council_review_followups 후속조치 보고와 증빙 확인표
council_check_figures 금액·비율 산술검사

일반 흐름은 준비표 → 근거 검색 → 실제 근거 선택 → 답변카드 → AI 초안 작성 → 초안·수치 점검 → 담당자 확인 → 회의 후 증빙 정리입니다. 준비표가 자동으로 모든 검색을 실행하지는 않습니다. 각 도구가 다음 단계에 필요한 인자와 확인사항을 제공합니다.

근거 도구의 snapshot_id와 event_id는 실제 검색 결과에서 가져와야 합니다. 임의로 만든 식별자는 거부합니다. 후속조치 후보는 council_get_evidence(collection="followup_items")로 확인합니다. 스냅샷이 만료되면 다시 검색해야 합니다.

설치·교체 순서

  1. 기존 버전과 환경설정은 백업하고, ZIP의 전체 소스를 별도 시험 폴더에 풉니다. 신규 파일 2개만 복사하면 응답·등록 계층 수정이 빠집니다.
  2. Python 3.11 또는 3.12 환경에서 python -m pip install -r requirements.txt를 실행합니다. 이번 실제 검증 환경은 Python 3.12 / MCP SDK 1.30.0입니다.
  3. 운영 환경에 설정한 CLIK_API_KEY를 그대로 유지하고 UIJEONG_PROFILE=work를 설정합니다. 이 패키지에 인증키를 넣지 않았습니다. .env.example은 참고용이며 자동으로 읽히지 않습니다.
  4. 로컬은 python uijeong_mcp.py, HTTP는 기존 배포 방식에 따라 python uijeong_mcp.py --http로 시작합니다. HTTP의 허용 호스트와 Bearer 인증 설정은 README를 따릅니다.
  5. 클라이언트 연결을 다시 읽고 council_status()에서 버전 2.2.0을 확인합니다. work 프로필에서 도구 11개가 보여야 합니다.
  6. council_status(live=True)로 운영 환경의 실제 API 연결을 확인하고, 의회·주제·기간을 지정해 소량 검색부터 확인합니다. 이 단계는 실제 외부 API를 호출합니다.
프로필 도구 수 권장 용도
core 5 근거 검색과 기존 준비자료 중심
work 11 신규 실무 흐름을 사용하는 기본 권장 설정
lite 19 기존 보조 기능도 함께 활용
full 31 개발·전체 기능 검증

환경변수를 생략하면 기존 호환성을 위해 full로 동작합니다. 배포 템플릿과 설정 예시는 work를 사용합니다. 정적 Bearer 인증을 지원하지 않고 OAuth만 받는 클라이언트에는 별도 인증 연계가 필요합니다. 이 버전에 OAuth 로그인은 구현하지 않았습니다.

검증 결과와 적용 범위

  • 제공 원본: pytest 211건 통과.
  • 개선본: pytest 247건 통과. 신규 실무·오류 경계 검사 36건 추가.
  • 기존 회귀 점검 25건과 오프라인 점검 16건 통과.
  • 실제 MCP SDK로 stdio와 TCP Streamable HTTP 통신, 신규 도구 호출, 구조화 결과, 오류 전달, 인증·호스트·Origin·요청 크기 제한 확인.
  • 기존 프로필 개수 검사 2건은 추가 도구 수에 맞게 lite 19개, full 31개로 갱신. core 5개 검사는 유지.

이 검증은 외부 API 호출 없이 수행했습니다. 실제 CLIK 키의 현재 유효성, 운영 서버 반영, 전국 회의록 검색 품질을 이번 시험으로 확인한 것은 아닙니다. 실제 Render/GitHub 서비스도 변경하지 않았습니다. 기존 출처 목록과 과거 관측 기록은 보존했으며 2026-09-19 전국 사이트 재조사를 수행하지 않았습니다.

전체 확장 기획

우선순위 다음 개발 완료 판단 기준
1. 부서 시범 운영 실제 회기 1개·핵심 주제 3개로 준비부터 회신까지 사용 발언·쪽수의 원문 일치, 담당자가 수정한 항목, 준비시간·누락사항 기록
2. 자료 수용 확대 우선 의회 3~5곳의 직접 어댑터, PDF/HWPX 추출 형식별 표본에서 발언·안건 경계와 원문 위치 검증
3. 기관 협업 사용자 인증, 부서별 권한, 공동 후속조치 장부, 변경 이력 타 부서 자료 접근 제한과 수정 이력·복구 검증
4. 법령·재정 연결 현행 법령·자치법규·지방재정 API 연계 기관·회계연도·단위·시행일 일치와 출처 재현

현재 직접 조회 어댑터는 CLIK와 광주 서구의회 홈페이지입니다. 전국 의회 디렉터리와 코드 목록은 탐색 기반이며 모든 의회 홈페이지의 본문 수집을 완료한 것이 아닙니다. 기존 API 안내서 docs/data-api-guide.md를 함께 제공하며, 이번 실무 기능에는 추가 API 키가 필요하지 않습니다. 법령·지방재정 API와 OCR, 공동 장부는 후속 개발 범위입니다.

성공 기준은 “의원 질문을 얼마나 잘 맞혔는가”보다 “원문과 수치가 정확한가, 답변 준비 누락이 줄었는가, 후속 회신이 확인 가능한가”로 잡는 것이 적절합니다. 최종 답변·제출·이행 판정은 담당자의 검토와 기관 절차를 거칩니다.
